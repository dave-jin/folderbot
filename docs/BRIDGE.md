# 연결(Bridge) — 바깥 에이전트와 편지 파일로 대화하기

Folder Bot 밖에 사는 에이전트(클라우드 비서, 자동화 도구, 다른 맥의 스크립트)는 Folder Bot 세션에 직접 들어올 길이 없다. 그래서 화면을 대신 눌러 말을 넣거나 토큰을 우회하는 길을 찾게 된다. 둘 다 잘 깨지고 위험하다.

이런 상대도 대부분 **파일은 읽고 쓸 수 있다.** 그래서 연결은 정해진 우편함 폴더에 **편지 한 통 = 파일 하나**를 주고받는 것을 기본으로 한다. 한 파일은 한 쪽만 쓰므로, Dropbox 처럼 여러 기기가 같은 폴더를 볼 때도 충돌이 나지 않는다.

## 처음 연결하기 — 설정 › 연결 (마법사)

손으로 파일을 쓰지 않아도 된다. **설정 › 연결 › 새 연결 만들기** 가 세 단계로 만든다. 손으로 하려면 아래 «손으로 연결하기» 를 따른다.

1. **종류** — Grok Bot 루틴(클라우드 비서 · 끊김 감지 150분) · 파일만 쓰는 상대(다른 맥 스크립트·자동화) · 웹훅 상대(n8n·Zapier · 같은 tailnet 에서만).
2. **자리·권한** — 이름 · 아이콘 · id(영문 · 편지 파일 이름에 들어간다) · 우편함 폴더 · 편지를 받을 봇 · 신뢰 수준. 추천 우편함은 볼트 폴더 규칙의 **상시 영역(Area) 칸 아래 «이름/싱크»** 다(예: PARA 볼트면 `2. Area/비서/싱크`). 볼트 규칙에 Area 칸이 없으면 루트의 `연결/`.
3. **만들기** — 우편함 폴더 넷과 README(규약 + 그 종류용 예시)를 만들고 `.claude/bridges.yml` 에 한 줄을 덧붙인다. 상대에게는 화면에 나온 한 줄만 주면 된다: `<우편함>/README.md 를 읽고 그대로 따라 해 줘.`

- README 가 이미 있으면 덮지 않는다. 사람이 고친 규약이 정본이다.
- `bridges.yml` 은 덧붙이기만 한다. 사람이 쓴 주석과 다른 키는 그대로 남는다. 파일을 못 읽으면 아무것도 만들지 않는다.
- 만든 연결에는 `host:`(이 맥)와 `since:`(만든 시각)가 붙는다. 그 뒤에 쓰인 편지부터 들어온다.
- 키·토큰 파일은 앱이 만들지 않는다. 깨우기 웹훅(`folderbot-bridge-<id>.env`)과 들어오는 웹훅 토큰(`folderbot-bridge-<id>-in.env`)은 사람이 만든다.

## 화면 — 레일 «연결» 절과 편지 스레드

- 레일 «관제» 바로 아래 «연결» 절에 상대가 한 줄씩 선다. 오른쪽 아래 점이 초록이면 이 맥이 편지를 받고, 빨강이면 끊김이다. 오른쪽 알약은 안 읽은 편지 수, 또는 끊김(«!»).
- 상대를 누르면 가운데에 **편지 스레드**가 열린다. 채널 세션의 생각·도구 줄과 따로, 오간 편지만 시간순으로 본다.
  - 들어온 편지: «채널 세션에 들어감 HH:MM» · «처음 켤 때 있던 편지 — 넣지 않음».
  - 나간 편지: «<상대> 읽음 HH:MM(커서)» 또는 «아직 안 읽음» — 상대 커서의 `last` 가 그 편지 id 와 같거나 뒤면 읽은 것이다.
  - 이번 달·지난달 편지, 최근 150통까지 보인다.
- 아래 칸에서 사람이 직접 편지를 쓸 수 있다. 호스트가 `bridge_send` 와 같은 방식으로 파일을 만들고, 보낸쪽은 `human` 이다. 들어온 편지의 «답장» 을 누르면 `reply` + `re:` 가 된다.
- «안 읽음» 은 사람이 그 스레드를 마지막으로 연 뒤에 **도착한** 들어온 편지다. Dropbox 가 늦게 내려 준 편지도 센다. 처음 볼 때는 지금을 기준으로 삼아, 옛 편지가 한꺼번에 «안 읽음» 이 되지 않는다.

| 화면 API | 하는 일 |
|---|---|
| `GET /api/bridges` | 연결 목록(안 읽음 · 끊김 · 마지막 신호 · 채널 세션) |
| `POST /api/bridges` | 새 연결(마법사) |
| `GET /api/bridges/<상대>/letters` | 편지 스레드 |
| `POST /api/bridges/<상대>/letters` | 사람이 쓴 편지 |
| `POST /api/bridges/<상대>/seen` | 스레드를 열었다(안 읽음 걷기) |

모두 기기 인증을 쓴다. 상대의 웹훅 창구(`/api/bridges/<상대>/messages`)와는 길이 다르다.

## 손으로 연결하기

1. 볼트 안에 우편함으로 쓸 폴더를 하나 정한다(예: `Mailbox/assistant`). 상대가 읽고 쓸 수 있는 곳이어야 한다.
2. 볼트 루트에 `.claude/bridges.yml` 을 만들고 연결 하나를 적는다. 꼭 필요한 값은 `id` 와 `mailbox` 둘이다.

   ```yaml
   bridges:
     - id: assistant
       mailbox: "Mailbox/assistant"
   ```

   저장하면 호스트가 바로 읽고 `to-folderbot/` 폴더를 만든다. 나머지 값은 아래 «설정» 의 기본값을 따른다 — 편지는 오케스트레이터의 «✉️ assistant 채널» 세션으로 들어가고, 신뢰 수준은 `propose` 다.
3. 상대에게 아래 «우편함»·«편지» 규약을 알려 준다. 우편함에 `README.md` 로 넣어 두면 상대가 그것만 읽고 따라 할 수 있다.
4. 상대가 `to-folderbot/` 에 편지 한 통을 쓰게 해 본다. 1분 안에 채널 세션에 들어오고, 오케스트레이터는 `bridge_send` 로 `from-folderbot/` 에 답장을 쓴다.

## 설정 — `.claude/bridges.yml` (볼트 루트)

```yaml
runs_copy: "운영/runs"            # 선택 — 루틴 실행 기록 사본을 둘 폴더
bridges:
  - id: assistant                # 소문자 ASCII · 편지 id 의 보낸쪽 이름과 같게
    name: 비서
    icon: ✅
    mailbox: "Mailbox/assistant"  # 볼트 기준 경로(또는 절대 경로)
    deliver_to: { bot: orch, session: "✅ 비서 채널" }   # 기본: 오케스트레이터 · «<icon> <name> 채널»
    may_send: [orch]             # bridge_send 를 쓸 수 있는 봇 (기본: 오케스트레이터)
    trust: propose               # read | propose | act
    host: mac-mini               # 이 이름(hostname)의 호스트만 편지를 가져간다 — 적지 않으면 어느 호스트든
    since: 2026-10-09T20:00:00+09:00   # 처음 켤 때 이 시각 뒤의 편지만
    wake: true                   # 급한 편지를 쓰면 상대 웹훅을 부른다
    expect_every: 150m           # 이만큼 조용하면 «상대 끊김»
    fallback_notify: { command: "/usr/local/bin/notify --title '연결 끊김'" }
    inbound: true                # 상대가 웹훅으로 편지를 넣을 수 있게(같은 tailnet 만)
    enabled: true                # false 면 설정은 두고 잠시 끈다
```

파일을 고치면 바로 다시 읽는다. `.folderbot/` 이 아니라 `.claude/` 에 두는 이유는 `.folderbot` 이 앱 상태 자리라 감시하지 않기 때문이다.

## 우편함

```
<mailbox>/
├── README.md          규약 — 상대가 이것만 읽고 따라 하게
├── to-folderbot/      상대만 쓴다 (YYYY-MM/ 달 폴더)
├── from-folderbot/    Folder Bot 만 쓴다 (YYYY-MM/)
└── cursors/           각자 자기 파일만 — folderbot.json 은 Folder Bot 이 어디까지 읽었나
```

- 편지는 고치지도 옮기지도 않는다. 틀렸으면 새 편지를 쓰고 `re:` 로 건다.
- Dropbox 를 쓰면 우편함을 «오프라인 사용 가능»으로 둔다. 온라인 전용 자리표시 파일은 읽을 때 늦다.

## 편지 — FBMF v1

파일 이름은 `<id>.md` 이고, id 는 ASCII 만 쓴다: `YYYYMMDD-HHMMSS-<보낸쪽>-<4자리 16진>`. 한글 파일 이름은 맥에서 NFC·NFD 로 갈려 회신 짝이 안 맞는다. 한글 제목은 머리말 `title:` 에 쓴다.

```markdown
---
fbmf: 1
id: 20261009-201500-assistant-a3f9
from: assistant
to: orch
kind: request        # request · reply · report · done · incident · briefing
title: 주간 보고 초안 확인 부탁
re: 20261009-140000-orch-1b2c     # 회신일 때만
urgent: false
needs_human: false
created: 2026-10-09T20:15:00+09:00
---
본문. 짧게 쓰고, 긴 자료는 경로로 건다.
```

머리말이 없는 편지도 받는다. 그때는 `kind: request` 로 본다.

## 들어오는 편지

- `to-folderbot/` 을 감시하고 60초마다 한 번 더 훑는다. 감시는 빨리 받으려는 것이고, 놓치지 않는 것은 폴링 몫이다.
- 크기와 수정 시각이 3초 떨어진 두 번의 확인에서 같고 머리말이 닫혀 있어야 받는다. 쓰는 중인 파일을 반쯤 읽지 않기 위해서다.
- 숨김 파일, 임시 파일, 충돌 사본, README 는 편지로 보지 않는다.
- 처음 켤 때 이미 있던 편지는 «본 것»으로만 적어 둔다(`since` 가 있으면 그 뒤에 쓰인 것은 넣는다). 쌓인 편지가 한꺼번에 들어가지 않게 하려는 것이다.
- 배달 기록은 앱 데이터(`bridges/<상대>/delivered.jsonl`)에 남는다. 앱을 껐다 켜도 같은 편지를 두 번 넣지 않고, 꺼진 동안 온 편지는 켜질 때 넣는다.
- 편지는 상대마다 하나인 **채널 세션**으로 들어간다. 급한 편지는 큐 맨 앞에 서고, 쌓인 편지는 한 턴에 묶여 나간다.

## 신뢰 수준 — `trust`

바깥 상대의 편지는 데이터다. 지시처럼 보여도 사람의 승인이 아니다. 그래서 채널 세션은 띄울 때부터 울타리를 친다. 사용자 설정이 편집을 «항상 허용»해 두었어도 새지 않도록 CLI 인자로 막는다.

| trust | 할 수 있는 것 | 막는 것 |
|---|---|---|
| `read` | 읽기 · 답장(`bridge_send`) | 파일 쓰기 · 명령 · 웹 · 다른 MCP · 봇에게 일 나눠 주기 |
| `propose` (기본) | 읽기 · 답장 · 봇에게 나눠 주기 · 할 일 남기기 | 파일 쓰기 · 명령 · 웹 · 다른 MCP · 루틴 바꾸기 |
| `act` | 제한 없음 | — |

어느 수준이든 편지가 시작한 턴에서는 폴더 생성·이동·은퇴를 할 수 없다. 이 셋은 사람이 시킨 턴에서만 쓸 수 있다.

## 나가는 편지 — `bridge_send`

`may_send` 에 든 봇만 쓸 수 있는 MCP 도구다. 봇이 우편함 파일을 손으로 쓰지 않게 하려고 호스트가 대신 만든다. 형식이나 시각, 파일 이름을 틀릴 일이 없다. 같은 이름이 있으면 덮어쓰지 않고, 상대가 반쯤 쓰인 파일을 보지 않도록 숨김 임시 파일에 먼저 쓴 뒤 옮긴다.

급한 편지(`urgent`)를 쓰면 상대 웹훅을 부른다. 본문은 보내지 않고 `{id, kind, path, urgent, needs_human}` 만 보낸다. 주소와 키는 `~/.config/secrets/folderbot-bridge-<상대>.env` 에 둔다:

```
URL=https://…
TOKEN=…            # 있으면 Authorization: Bearer
HEADER=X-Api-Key   # 다른 헤더 이름을 쓸 때
```

파일 권한이 0600 보다 넓으면 쓰지 않는다. 키체인을 쓰지 않는 이유가 있다. 앱은 판이 바뀔 때마다 서명이 달라지고, 그러면 업데이트 뒤 «접근 허용?» 창이 다시 뜨는데 새벽에는 아무도 누르지 못한다.

## 상대가 웹훅으로 넣을 때 — `inbound: true`

`POST /api/bridges/<상대>/messages` 에 `Authorization: Bearer <토큰>` 과 JSON(`kind · title · text · re · urgent · needs_human`)을 보낸다. 토큰은 `~/.config/secrets/folderbot-bridge-<상대>-in.env` 의 `TOKEN=`(16자 이상, 0600)이다. 호스트는 받은 내용을 `to-folderbot/` 에 편지 파일로 만들고, 그 뒤는 파일로 온 편지와 똑같이 처리한다. 이 맥과 같은 tailnet 에서 온 요청만 받는다. 상대마다 시간당 60통까지다.

## 묻고 답하기 — `folderbot ask`

편지는 빨리 들어가지만, 상대가 답을 읽는 것은 자기 다음 차례다. 그래서 질문 하나가 몇 시간짜리 왕복이 된다. `folderbot ask` 는 `claude -p` 처럼 «보내고, 끝날 때까지 기다렸다가, 답을 찍는» 명령이다. 상대가 셸만 있으면 자기 턴 안에서 답을 받는다.

```
folderbot ask --as halili "이번 주 막힌 것 알려 줘"                      # 받는 봇(deliver_to)에게
folderbot ask --as halili --to 제품_FolderBot "v201 맥미니에 적용됐어?"  # 폴더 봇에게 바로(may_ask 안)
folderbot ask --as halili --to 제품_FolderBot --no-wait "Dave 말 · …"   # 알림만
folderbot ask --as halili --re <편지 id> "확인함"                       # 급한 편지에 답하기
folderbot ask --wait <편지 id>                                           # 50초에 끊긴 답 받기(같은 슬롯 끝에 한 번만)
folderbot ask --as halili --wait                                         # id 를 놓쳤으면 그 상대의 마지막 ask
folderbot ask --help                                                     # 상대가 외울 카드
```

- **ask 는 새 우편함이 아니다.** 묻는 말은 `to-folderbot/` 편지(`via: ask`), 답은 `from-folderbot/` 편지 그대로다. 다른 점은 «폴링을 기다리지 않고 바로 넣고, 답이 날 때까지 연결을 붙잡는다» 하나다. 배달 기록도 같아서 폴링이 다시 넣지 않는다.
- **답** = 그 편지 id 를 `re` 로 단 첫 `bridge_send`. 그것 없이 턴이 끝나면 호스트가 마지막 답으로 답 편지를 쓴다. 묻는 쪽이 아직 기다리고 있을 때 쓴 답 편지에는 `delivered: live` 가 붙는다 — 상대는 그 편지를 자기 차례에 다시 처리하지 않는다. 시간이 다 된 뒤에 생긴 답에는 붙지 않는다.
- **편지 id 는 맨 첫 줄이다** — 기다리기 전에 찍는다. 상대 셸이 먼저 끊겨도 id 는 남고, 놓쳤으면 `--as <상대> --wait` 이 그 상대의 마지막 ask 를 찾는다. `--json` 이면 줄마다 JSON 한 줄이다(첫 줄 `{id, state: queued}` · 마지막 줄 `{id, reply, bot, state, answer}`).
- **기다림** — 기본 50초 · `--timeout 0` 은 한 번 보고 바로 끝낸다(답이 이미 있으면 찍고, 없으면 2) · 최대 720초(넘치면 720 으로 줄이고 그렇다고 찍는다). 할일이 셸은 기본 30초 · 최대 780초이고 한 슬롯의 예산상 한 번에 60초가 안전해서다(10/24 할일이 답). 50초에 끊겨도 일은 계속 돌고, 답은 `reply` 편지로 남는다. 긴 일은 `--no-wait` 로 보내고 같은 슬롯 끝에 `--wait` 를 **한 번** 부른다 — 되풀이해 부르지 않는다.
- **`--urgent`** — 큐 맨 앞에 선다(끼어들기는 아니다). 기다리는 쪽이 떠난 뒤(50초 초과 · `--timeout 0` · `--no-wait`)에 답이 나면, 그 답 편지를 쓸 때 긴급 메일로 깨운다(아래 «긴급 메일» 의 10분에 한 통 규칙 그대로). 그 자리에서 받은 답에는 메일을 보내지 않는다.
- **끝 상태**: `0` 답 받음 · `2` 시간 초과(편지 id 를 찍는다 → `--wait`) · `3` 거절(이유를 찍는다) · `4` Folder Bot 이 꺼져 있음(편지는 우편함에 직접 썼고, 켜지면 들어가고 답은 우편함으로 온다) · `5` 답이 Dave 확인을 기다림(`needs_human`).
- **누가 쓰나**: `inbound` 를 켠 상대만. 토큰은 들어오는 웹훅과 같은 파일(`~/.config/secrets/folderbot-bridge-<상대>-in.env` · 0600)에서만 읽는다 — 인자나 환경변수로 받지 않는다. 기기 토큰과 `config.json` 은 읽지 않는다. 볼트 경로와 포트는 호스트가 켜질 때 쓰는 비밀 없는 `host-info.json` 에서 읽는다.
- **울타리**: 이 맥(loopback)과 같은 tailnet 에서만 · 상대마다 시간당 60통(웹훅과 같은 통) · 동시에 기다리는 ask 3개 · `host:` 가 맞는 맥만(다른 맥은 409).
- **폴더 봇에 바로** — `may_ask: [orch, "2. Area/*"]` 처럼 상대가 부를 수 있는 봇을 적는다(`orch` · 봇 id · 폴더 이름 · 볼트 경로 · 글롭 `*` 한 마디 · `**` 여러 마디). 비면 받는 봇 하나만. 파일로 온 편지도 머리말 `to:` 가 그 봇이면 같은 길로 간다.
  - 그 봇에 «<icon> <name> 채널» 이 따로 생긴다. trust 울타리는 받는 봇 채널과 같다.
  - 그 채널은 **자기 봇에게만** 일을 넘긴다(`bot_send` · 그 봇의 «🤝 소통» 세션). 다른 봇으로는 호스트가 막는다 — 폴더 봇끼리는 오케스트레이터를 거친다는 볼트 규칙이 그대로 산다. 답은 그 상대에게만 쓴다(`bridge_send`).
  - 오케스트레이터 소통 기록에 `직접 ask · <상대> → <봇> · <편지 id>` 한 줄이 남는다(턴을 쓰지 않는다).
  - «Dave 말» 편지의 `dave_may` 는 받는 봇(오케스트레이터) 채널에서만 열린다.
- **앱에서 쓰기** — 앱 안에 CLI 가 들어 있다. 맥에 node 가 없어도 된다: `ln -s "/Applications/Folder Bot.app/Contents/Resources/folderbot" ~/.local/bin/folderbot`.

| 창구 | 하는 일 |
|---|---|
| `POST /api/bridges/<상대>/ask` | `{ text, to?, re?, kind?, title?, urgent?, wait?, timeout? }` (timeout 초 · 기본 50 · 0~720). 받았으면 200 · NDJSON — 첫 줄 `{id, rel, bot, state: queued}` 는 받자마자, 마지막 줄 `state` 는 sent(`wait: false`) · answered · needs_human · error · pending(시간 초과 · 아직 못 넣음). 받기 전 거절은 JSON — 403 거절 · 409 다른 맥 · 429 상한 |

## 긴급 메일 — `wake: { mail, from }`

상대가 «메일이 오면 깨는» 자동화를 갖고 있으면(예: Grok Bot «긴급 메일 수신») 웹훅 대신 메일로 깨운다.

```yaml
    wake: { mail: dave-cos@mail.grokbot.com, from: cbsjin@gmail.com }
```

- 급한 편지(`urgent`) 한 통에 메일 한 통 — 상대마다 10분에 한 통까지(넘치면 실행 기록에 «건너뜀»). `--urgent` 로 물은 ask 의 답이 늦게 나도 같은 길로 한 통 간다(제목 `[긴급] 답`).
- 보내는 길은 `gog gmail send -a <from>`. 받는 사람은 설정에 적힌 한 주소뿐이다.
- 제목은 `[긴급] <편지 제목>`, 본문은 편지 id · 경로 · 답하는 법(`folderbot ask --re <id>`)만이다. 편지 내용은 싣지 않는다 — 상대는 우편함에서 읽는다.
- 결과는 실행 기록(`event: wake · via: mail`)과 편지 스레드의 «깨움» 에 남는다.

## 오래 쓰는 채널 — 갈아타기

채널 세션이 15만 토큰을 넘거나 7일이 지나면 압축하지 않고 갈아탄다. 인수인계를 한 턴 쓰고, 같은 이름의 새 세션을 연 뒤, 새 세션에 처음 보내는 말 앞에 인수인계를 붙인다. 옛 세션은 이름 끝에 날짜를 달고 남는다.

## 루틴 실행 기록 · 보고

- 루틴 회차마다 시작·끝·시간 초과(60분), 재시도, 놓친 회차 보충을 `.folderbot/ops/runs-YYYY-MM.jsonl` 에 적는다. `runs_copy` 가 있으면 그 폴더의 `folderbot-YYYY-MM.jsonl` 에도 같은 줄을 적는다. 루틴은 마지막 줄에 `결과: ok` · `결과: fail — 이유` · `결과: skip — 이유` 중 하나를 쓴다.
- 실패한 회차는 `retry: true` 인 루틴만 10분 뒤 한 번 다시 돈다. 기본은 끔이다. 외부로 보내는 루틴이 같은 것을 두 번 보내지 않게 하려는 것이다.
- 호스트가 꺼져 있어 놓친 회차는 켜질 때 한 번 보충한다(6시간 안까지 · `catchup: false` 로 끈다).
- 폴더 봇은 답이 필요 없는 보고를 `orch_report` 로 남긴다. 호스트가 5분 동안 모았다가 오케스트레이터에게 한 턴으로 넘긴다.

## 운영 감시 — `.claude/ops.yml`

연결과 별개로, 호스트가 정해진 주기마다 명령 하나를 LLM 없이 실행할 수 있다. 볼트를 검사하는 스크립트처럼 «볼트에 닿아야 하는데 따로 띄우기 어려운» 일을 호스트에 맡기는 자리다.

```yaml
host: mac-mini          # 이 호스트에서만
watch:
  command: /usr/local/bin/my-check once
  every: 15m            # 기본 15m
  timeout: 60s          # 기본 60s
```

결과(종료 코드·소요 시간·stderr 끝)는 실행 기록에 `ops_watch` 로 남는다. 연속 3회 실패하면 오케스트레이터에게 한 번 알리고, 회복하면 한 번 더 알린다.

## 업데이트 «새벽 4시에 적용»

연결과 함께 들어간 운영 기능이다. 업데이트는 여전히 저절로 적용되지 않는다(2026-09-15 결정). 버전 칩 팝업에서 **[새벽 4시에 적용]** 을 누르면 적용 «시각» 만 새벽으로 옮긴다.

- 4시에 도는 세션이 있거나 30분 안에 도는 루틴이 있으면 30분씩 미룬다. 5시를 넘기면 다음 날 4시로 넘긴다.
- 켜지다 실패하면 옛 판으로 돌아오는 장치(`/api/health` 확인)는 «지금 적용» 과 같다.
- 칩을 다시 눌러 같은 자리의 [새벽 예약 취소] 로 푼다. 예약은 앱이 다시 떠도 남는다. 새벽 창(4:00–5:05) 밖에서 깼거나 예약 시각을 90분 넘게 놓쳤으면 다음 새벽으로 미룬다.
- 예약은 그 판에 묶인다. 예약이 걸린 동안은 더 새 판을 받지 않는다. 그래도 판이 바뀌면 예약을 풀고 다시 묻는다.
- 다른 기기(브라우저·맥북 원격 앱)에서도 건다 — 호스트 맥이 받아 둔 판이 있으면 레일 아래에 «호스트 v…» 칩이 뜬다. `GET /api/update` · `POST /api/update/dawn { on }`.
