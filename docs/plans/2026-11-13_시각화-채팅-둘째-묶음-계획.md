# 시각화 채팅 둘째 묶음 «그림으로 받는 답» — 구현 계획

**Goal:** 순서 · 비교 · 숫자가 든 답을 봇이 코드 울타리 블록으로 쓰면 채팅이 카드로 그리고, 봇이 자유롭게 만든 html 파일은 말풍선 안의 격리된 미니 창에서 연다. 봇에게는 그 쓰는 법을 규칙으로 알려 준다.

**Spec:** 볼트 `2. Area/제품_FolderBot/01_기획/2026-11-12_기획_시각화-채팅과-폴더-개요.md`(§3 둘째 · §4) · 목업 `03_디자인/2026-11-12_시각화-채팅-목업/시각화-채팅-목업.html` 둘째 구역(11/12 Dave «승인 — 계획 쓰고 첫 묶음부터» · 11/13 «…함께 개발 및 배포해줘»).

**이번 묶음 밖:** 폴더 개요 · 보여 주기 보기 · 오피스 파일 미리보기 · 블록을 화면 가득 키우는 «크게»(창의 한 틀이 생기는 «부품» 걸음 뒤) · 꺾은선 차트 · 문서 창의 마크다운 보기에서 블록 그리기.

**Tech:** TypeScript · React client · Node host · vitest(`test/unit`) · 스모크 `test/smoke.mjs` · 폭 검사 `test/fit.mjs`.

## Global Constraints

- 판정과 읽기는 순수 모듈(`src/core`)에 두고 유닛으로 잰다. 화면 모듈은 그 결과를 DOM 으로 그리기만 한다(첫 묶음과 같은 길).
- 블록은 **코드 울타리**로 받는다(mermaid 와 같은 길). 못 읽으면 코드 그대로 두고 이유를 한 줄 붙인다 — 조용히 틀리게 그리지 않는다. 옛 판에서는 코드로 보인다.
- 스트리밍 중에는 그리지 않는다. 답이 끝난 뒤 **그리기 전에**(`useLayoutEffect`) 한 번에 바꾼다.
- 새 의존성을 들이지 않는다. 차트는 HTML 과 CSS 로 그린다.
- 값은 눈금에서 고른다(`styles.css` 맨 위 «눈금» · `test/unit/cssScale.test.ts`). 색은 있는 토큰만 쓴다(`--done` · `--hold` · `--err` · `--w`).
- 새 클래스 이름은 `vb-` · `mc-h` 로 시작한다(겹침 0 확인).
- 미니 창의 스크립트는 누를 때까지 돌지 않는다 — 긴 대화를 열 때마다 봇이 만든 스크립트가 저절로 돌면 화면이 멈출 수 있다.
- 데스크톱과 폰(390pt)을 함께 잰다.

## Task 1 — 블록 읽기 (`src/core/visualBlocks.ts`)

울타리 이름은 `steps` · `compare` · `chart`(`VISUAL_LANGS`). 줄 단위 글이라 옛 판에서 코드로 보여도 읽힌다.

| 블록 | 쓰는 법 | 못 읽는 경우(→ `null`) |
|---|---|---|
| `steps` | `title: 제목`(선택) 뒤 줄마다 `[x] 끝난 단계 \| 덧붙임` · `[>] 지금` · `[ ] 남은` | 단계가 2개 미만 · 12개 초과 · 모양이 다른 줄 |
| `compare` | `title:`(선택) · `# 안 이름`(추천은 끝에 ` *` 또는 `(추천)`) 아래 `항목: 값` | 안이 2개 미만 · 6개 초과 · 항목 없는 안 · 모양이 다른 줄 |
| `chart` | `title:` · `unit:`(선택) 뒤 `이름: 숫자`(끝에 ` ~` = 아직 확정 아님) | 값이 2개 미만 · 24개 초과 · 숫자가 아닌 값 |

- `parseVisual(lang, src): StepsBlock | CompareBlock | ChartBlock | null`.
- `StepsBlock { kind, title, steps: { state: 'done'|'now'|'todo', label, note }[], at }` — `at` 은 지금 단계 번호(없으면 끝난 수).
- `CompareBlock { kind, title, keys: string[], options: { name, rec, rows: Record<string,string> }[] }` — `keys` 는 처음 나온 순서.
- `ChartBlock { kind, title, unit, layout: 'cols'|'rows', points: { label, value, text, soft, pct }[] }` — `pct` 는 가장 큰 절댓값 대비 0~100. 값이 일곱 이상이거나 이름이 10자 · 값 글이 6자를 넘으면 `rows`(가로 막대 — 독립 검토 뒤 좁혔다).
- 숫자는 `1,200` · `-3.5` · `24명` 을 읽는다(뒤 글자는 보이는 글에만 쓴다).

**검사** `test/unit/visualBlocks.test.ts`: 목업의 세 예시 · 한글 머리말(`제목:`) · 값에 든 `:`(«11:30») · 이름에 든 `:` · 모양이 다른 줄 → null · 개수 한도 · 음수 · `layout` 갈래.

## Task 2 — 블록 그리기 (`src/client/visualBlocks.ts` · `Sheets.tsx` · `styles.css`)

`renderVisualBlocks(root): number` — `pre > code.language-{steps|compare|chart}` 를 `.vblk` 카드로 바꾼다. `Md` 의 `useLayoutEffect` 에서 `decorateCode` **앞**에, 스트리밍이 아닐 때만 부른다.

| 블록 | 머리 | 본체 | 단추 |
|---|---|---|---|
| 단계 | 제목(없으면 «어디까지 왔나») · «단계 N · 지금 k번째» | 5개까지 가로 줄, 넘으면 세로 줄 | — |
| 안 비교 | 제목(«안 비교») · «N개» | 안마다 카드(추천은 테두리 + «추천») · 폰은 옆으로 넘김 | [표로 보기] ↔ [카드로 보기] |
| 숫자 | 제목(«숫자») · «막대 · 단위» | 세로 막대 또는 가로 막대 | [숫자 보기] ↔ [막대 보기] |

- 못 읽으면 코드 블록을 그대로 두고 아래에 `.vb-err` 한 줄(«블록을 못 읽었어요 — 코드로 둡니다»). 같은 블록을 두 번 손대지 않는다(`data-vb`).
- 봇 답은 `class` 를 못 실으므로(`sanitize.ts`) 카드 모양을 흉내 낼 수 없다.

**검사** 스모크: 스텁 답에 세 블록 + 깨진 블록 하나 → `.vblk` 셋(단계 5 · 지금 3번째 · 안 3개 중 추천 1 · 막대 5) · 깨진 것은 코드 + `.vb-err` · [표로 보기] 를 누르면 표 · 폰 폭에서 화면 밖 넘침 0.

## Task 3 — 격리된 미니 창 (`core/media.ts` · `core/visualBlocks.ts` · `client/mediaCards.ts` · `core/paths.ts`)

봇이 만든 html 파일을 답에서 한 줄에 혼자 적으면 카드가 된다(첫 묶음의 미디어 카드와 같은 판정).

- `mediaKind` 에 `html`(`.html` — `.htm` 은 호스트가 모르는 확장자라 뺐다) · `MediaCard.type` 에 `'html'` · `FILE_EXT` 에 `html`(혼자 적힌 `계산기.html` 이 칩이 되게).
- 카드: 머리 줄(점 셋 · 파일 이름 · «격리됨 · 볼트와 화면에 못 닿아요») · 본체(덮개 «미니 창 열기» → 누르면 그때 받아 틀에 넣는다) · 발([문서 창]).
- 틀: `<iframe sandbox="allow-scripts">` + `srcdoc`. 파일 글은 머리말 토큰으로 받아(`fetch` + `Authorization`) **주소에 토큰이 없는** 문서로 넣는다 — 문서 창 html 보기(`src=…&token=`)보다 좁다. `allow-same-origin` · `allow-popups` 를 주지 않는다.
- `miniDoc(html): string` — 맨 앞(doctype 바로 뒤)에 CSP 메타를 끼운다: `default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data: blob:; media-src data: blob:; font-src data:; form-action 'none'; base-uri 'none'`. 어느 스크립트보다 앞에 와야 하므로 `<head>` 를 찾지 않고 맨 앞에 둔다.
- `MINI_MAX = 512KB` — 넘으면 틀에 넣지 않고 «커서 문서 창에서 열어요».

**검사** 유닛: `mediaKind('a.html')` · `planCards` 에 html 카드 · `miniDoc`(doctype 유지 · 메타가 첫 `<script>` 보다 앞 · doctype 없는 글). 스모크: html 파일을 만들고 스텁이 한 줄에 적음 → `.mcard.mc-html` · 누르기 전 `iframe` 없음 · 누른 뒤 `iframe[sandbox="allow-scripts"]` 의 `srcdoc` 에 CSP · 틀 안 스크립트가 부모의 `window.__mini` 를 못 건드림 · 틀 안에서 호스트 API 를 불러도 답을 못 읽음.

## Task 4 — 봇에게 알려 주는 규칙 (`core/visualBlocks.ts` `VISUAL_RULES_MD` · `host/host.ts` · `host/registry.ts`)

- 시스템 프롬프트에 `DEVICE_RULES_MD` 다음으로 넣는다(옛 볼트에도 닿는다). 새 볼트의 `CLAUDE.md` 머리말에도 같은 글을 넣는다. 있는 볼트의 `CLAUDE.md` 는 건드리지 않는다.
- 글은 짧게: 언제 쓰나(순서 · 비교 · 숫자) · 세 블록의 쓰는 법 · html 미니 창(한 파일에 다 담고 바깥 주소를 부르지 않는다 · 답에서 파일 이름만 한 줄에) · 지어낸 값을 넣지 않는다 · 흐름 그림은 mermaid 그대로.

**검사** 유닛: 규칙 글에 적힌 예시 줄이 `parseVisual` 로 읽힌다(규칙과 읽기가 어긋나지 않게) · `VISUAL_LANGS` 의 이름이 글에 다 있다.

## Review Focus

- 미니 창의 틀이 볼트 · 토큰 · 부모 화면에 닿는 길이 있는가(`srcdoc` 에 토큰이 섞이는가 · 틀 속성이 넓어지는가).
- 블록 읽기가 조용히 틀리지 않는가 — 반만 읽은 블록을 그리지 않는가.
- 카드가 폰 폭을 넘지 않는가 · 스트리밍이 끝날 때 대화가 덜컹이지 않는가.
- 규칙 글이 시스템 프롬프트를 얼마나 늘리는가(모든 세션이 받는다).
- `FILE_EXT` 에 html 을 더해 엉뚱한 글이 칩이 되지 않는가.

## 독립 검토 뒤 고친 것 (2026-11-13)

코드만 주고 받은 검토에서 배포 전에 고칠 것이 셋 나왔다. 셋 다 재현한 뒤 고쳤다.

- **숫자 블록이 조용히 틀리게 읽었다.** `1.2억` 과 `8,000만` 을 1.2 대 8000 으로, `24명 (11:30 마감)` 을 30 으로 읽었다. 이제 값은 숫자 하나와 단위 글자뿐이고, 숫자 사이의 쌍점(`11:30`)은 가르는 자리가 아니며, 단위가 줄마다 다르면 `null` 이다.
- **미니 창이 스스로 바깥 주소로 갈 수 있었다.** 틀 안의 정책(`MINI_CSP`)은 틀의 이동을 못 막는다 — 링크 · `location.href` · `meta refresh` 로 요청이 1건 나가는 것을 브라우저로 재현했다. 앱 문서(`client/index.html`)에 `frame-src 'self'` 를 걸어 막았고(요청 0건), 두 번째 `load` 가 오면 틀을 걷고 덮개로 돌아간다.
- **단계 카드의 «남음» 단계가 깨졌다.** 상태 클래스 `todo` 가 할 일 줄의 전역 `.todo` 규칙을 물려받았다. 상태 · 변형 클래스를 모두 `vb-` · `mc-h` 로 시작하게 바꿨다.

같이 고친 것:

- 읽기 — 안 비교의 같은 항목 두 줄은 `null` · 줄 앞 글머리표는 뗀다 · 항목 이름이 `constructor` 여도 물려받은 값이 없다 · 숫자뿐인 `단위:` 는 값이다 · 세로 막대는 여섯까지(값 글이 6자를 넘어도 가로).
- 그리기 — **봇 답에서만** 그린다(`Md` 의 `visual`). 문서 창 · 캔버스 · 편지 · 내 말에서는 코드 그대로다. 답이 끊겨 울타리가 안 닫힌 반쪽 블록은 그리지 않는다(`fenceOpen`). 카드 안 글에는 파일 칩이 끼지 않는다.
- 미니 창 — 실패한 뒤에도 단추가 남아 다시 열 수 있다 · 열려 있을 때 «닫기» · 바깥 자료를 쓰는 html 은 «문서 창에서 여세요» 를 함께 알린다(`miniOutside`) · referrer 를 싣지 않는다 · `.htm` 은 뺐다(호스트가 모르는 확장자).
- 규칙 글 — 사람이 채팅에서 읽는 답에만 쓴다(파일 · 편지 · 루틴 보고에는 쓰지 않는다) · 숫자는 하나만 쓰고 단위는 `unit:` 에 · 개수 한도는 상수에서 온다.
- 알림 미리보기 — 블록의 줄 글 대신 «(단계 그림 · 제목)» 만 남긴다(`core/mdPlain`).

남긴 것: WebRTC · `dns-prefetch` 는 CSP 가 막지 못한다(틀이 아는 것은 그 파일 자신과 사람이 틀 안에 친 값뿐이다). 사파리(WebKit)에서 `frame-src` 가 틀의 이동을 막는지는 재지 못했다 — 스모크는 크롬으로 돈다.
