# 시각화 채팅 첫 묶음 — 구현 계획

**Goal:** 봇 답에 섞인 날 HTML 을 걸러 내고, 봇이 말한 그림·영상·음성·PDF 를 말풍선 안 카드로 펼쳐 그 자리에서 재생하며, 질문 카드에 답한 뒤 «무엇을 골랐는지» 가 대화에 남게 한다.

**Spec:** 볼트 `2. Area/제품_FolderBot/01_기획/2026-11-12_기획_시각화-채팅과-폴더-개요.md`(§3 첫째·셋째 + 거르개) · 목업 `03_디자인/2026-11-12_시각화-채팅-목업/시각화-채팅-목업.html`. 11/12 Dave 카드 «승인 — 계획 쓰고 첫 묶음부터».

**이번 묶음 밖:** 그림 블록(단계·안 비교·차트)·격리된 미니 창 · 폴더 개요 · 보여 주기 보기 · 오피스 파일 미리보기.

**Tech:** TypeScript · React client · Node host · vitest(`test/unit`) · 스모크 `test/smoke.mjs` · 폭 검사 `test/fit.mjs` · 맥 검사 `test/mac-qa.mjs`.

## Global Constraints

- 판정은 순수 모듈(`src/core`)에 두고 유닛으로 잰다. 화면 모듈은 그 결과를 그리기만 한다.
- 답 본문은 `marked` 가 만든 HTML 문자열이다 — 카드는 `previews.ts` 처럼 **그린 뒤 DOM 으로** 만든다. 스트리밍 중에는 손대지 않는다.
- 새 의존성을 들이지 않는다. 거르개는 node 유닛에서 돌아야 한다(`render.test.ts` 가 DOM 없이 돈다).
- 영상·음성은 `preload="none"` — 누를 때까지 받지 않는다. 그림은 `loading="lazy"`.
- 화면 글은 한국어 · `DESIGN.md` · `docs/LAYOUT.md`(폰 390pt). 데스크톱과 폰을 함께 잰다.
- 커밋·배포는 Dave 카드 승인 뒤에만 한다.

## Task 1 — 거르개 (`src/core/sanitize.ts`)

`sanitizeHtml(html: string): string` — **전부 글자로 돌리고, 허용한 태그만 우리가 다시 짓는다.**

- 태그 꼴(`<name attrs>` · `</name>`)을 정규식으로 찾는다. 허용 목록에 없거나 꼴이 어긋나면 그 `<` 를 `&lt;` 로 바꾼다(`<!`·`<?`·닫히지 않은 주석 포함). 닫힌 주석(`<!-- … -->`)은 통째로 지운다 — 글자로 돌리면 봇이 인용한 todo 줄의 `<!-- bot -->` 꼬리표가 드러난다.
- 허용 태그는 원문을 통과시키지 않는다 — 속성을 파싱해 허용 속성만 `name="escaped"` 로 **다시 써서** 낸다. `on*`·`style`·모르는 속성은 버린다.
- 주소 속성(`href`·`src`)은 `http:`·`https:`·`mailto:`·`tel:`·상대 경로·`#` 만 둔다. `img[src]` 는 여기에 `data:image/(png|jpeg|gif|webp);base64,` 를 더한다. 그 밖(`javascript:`·`vbscript:`·`data:text/html` · 제어문자로 감춘 것 · 스킴 자리에 이름 엔티티가 남은 것)은 속성을 버린다. `&amp;` 는 글자 `&` 로 본다(`R&D.md` 가 살아남는다).
- 속성 값에 든 수식 자리표는 지운다 — 거른 뒤 끼우는 KaTeX HTML 이 속성 안에 들어가지 않게.
- 허용 태그: marked 가 내는 것(`p h1-h6 ul ol li blockquote pre code hr br em strong del a img table thead tbody tr th td input`) + 글에 흔한 것(`details summary kbd sub sup mark span div u s b i small`). `input` 은 `type=checkbox` 일 때만(`checked`·`disabled`).
- 허용 속성: 공통 `title` · `class` 는 **화면이 아는 이름만**(`language-*`·`wlink`·`wimg`·`mathsrc`·체크 목록 둘 — 봇 답이 `class="mcard"` 로 카드 모양을 흉내 내지 못하게) · `a[href,target,rel,data-wiki]` · `img[src,alt,width,height,data-wiki]` · `th/td[align,colspan,rowspan]` · `ol[start]` · `details[open]` · `code[class]`.
- 끼우는 자리: `renderMarkdown` 에서 marked 뒤 · `fillMath` **앞**(KaTeX 출력은 우리가 만든 것이라 거르지 않는다). 봇 답과 내 말 모두 지난다.

**검사** `test/unit/sanitize.test.ts`: `<img src=x onerror=…>` 에서 `onerror` 사라짐 · `<script>` 글자로 · `[x](javascript:alert(1))` 의 href 사라짐 · `style` 사라짐 · 따옴표 안 `>` · 닫히지 않은 태그 · 대문자 태그 · 위키링크(`a.wlink[data-wiki]`·`img.wimg[data-wiki]`) 살아남음 · 코드 블록 안 글자 그대로 · 표·체크박스·`details` 살아남음 · 수식 자리표시 그대로. `render.test.ts` 기존 항목 통과.
**스모크:** 스텁 봇 답에 `<img src=x onerror="window.__xss2=1">` → `window.__xss2` 가 생기지 않는다.

## Task 3 — 미디어 카드 (`src/client/mediaCards.ts`)

**판정(`planCards`)** — 답의 블록(`p`·`li`)마다 «미디어 파일 참조만 있는가» 를 본다. 참조 = `decorate()` 가 만든 `.pchip[data-rel]`·`code.code-path[data-rel]`·`img.wimg` 가 아닌 것. 블록의 글이 참조와 구분 글자(공백 · `,` · `·`)뿐이면 «혼자 선 블록» 이다.

- 혼자 선 블록의 참조만 카드가 된다. 문장 속 참조는 칩 그대로.
- 그림은 이웃한 것끼리 한 묶음(갤러리)이고 묶음 하나가 카드 하나다. 영상·음성·PDF 는 하나가 카드 하나.
- 답 하나에 카드는 `cap` 개까지. 넘는 블록은 칩 그대로 둔다(이미 눌러 열 수 있다).
- 여러 곳에 걸린 이름(`matches > 1`)과 폴더는 카드로 만들지 않는다. `decorate()` 가 칩에 `data-multi` 를 남겨 `cardify` 가 알아본다(호스트는 여럿 걸리면 첫 번째를 `rel` 로 준다 — 표식이 없으면 엉뚱한 파일이 펼쳐진다).
- `![](상대경로.png)` 는 카드가 아니라 **그 자리 그림**이다 — marked 의 그림 해석기에서 `img.wimg[data-wiki]` 로 바꿔 위키 그림과 같은 길(있는 파일 확인 → 원본 주소)로 보낸다(`render.ts` `relImage`).
- 카드는 답이 그려진 뒤에 붙어 높이를 늘린다 — `fb:grew` 를 알려 맨 아래를 보고 있던 대화가 따라 내려가게 한다.

**그리기** — `cardify(root, botId, open)` 를 `Md` 의 `decorate()` 바로 뒤에서 부른다.

| 종류 | 본체 | 발 |
|---|---|---|
| 그림 한 장 | `<img loading="lazy">` · 누르면 문서 창 | 이름 |
| 그림 여러 장 | 4칸 격자 · 다섯째부터 «+N» · 누르면 그 그림을 문서 창 | «그림 N장» |
| 영상 | `<video controls preload="none" playsinline>` + ▶ 덮개(누르면 재생) | 이름 · [문서 창] |
| 음성 | `<audio controls preload="none">` | 이름 · [문서 창] |
| PDF | 쪽 모양 아이콘 + 이름 · 누르면 문서 창 | — |

- 원본 주소는 기존 `/api/bots/:id/raw?rel=…&token=…`(조각 응답이 이미 있다).
- PDF 첫 쪽 그림은 이번에 넣지 않는다 — iframe 으로 그리면 답을 그릴 때 PDF 를 받게 된다(«누를 때까지 받지 않는다» 와 어긋남). 목업과 다른 점으로 보고한다.
- CSS 는 `styles.css` `.mcard` — 폭 `min(440px, 100%)` · 폰에서는 줄 폭 전부.

**검사:** `media.test.ts` 의 `planCards` 표(혼자 선 블록 · 문장 속 · 이웃 그림 묶기 · cap · matches) · 스모크(픽스처 볼트에 png 둘·mp4·m4a·pdf → 스텁 답이 한 줄씩 적음 → `.mcard` 넷 · `video[preload=none]` · 문장 속 이름은 `.pchip`) · `fit.mjs` 에 폰 폭 넘침 0.

## Task 4 — 질문 답 요약 (`src/core/askDone.ts` · `App.tsx`)

- `askSummary(input, result)` → `{ rows: [{ header, question, picks: string[], free?: string, rest: string[], edited?: boolean }], partial: boolean } | null`.
  - 답 글은 세 모양이다: CLI `User has answered your questions: "Q"="A", … You can now continue…` · 호스트 `Your questions have been answered: …` · 고친 글이 있을 때 `The user answered: "Q"="A" selected preview:\n… notes: …`. 질문 글을 **아는 채로**(`input.questions`) `"Q"="` 를 찾아 다음 질문 표식 앞까지를 답으로 읽는다.
  - 여럿 고르기는 선택지 이름을 답에서 먼저 떼어 내고 남은 것을 «직접 쓴 글» 로 둔다(직접 쓴 글에 쉼표가 있어도 깨지지 않게). ` (고친 글로)` 꼬리는 `edited`.
  - 결과가 2000자에서 잘려 어떤 질문을 못 찾으면 `partial`. 하나도 못 찾으면 `null` → 종전 도구 줄 그대로.
- 화면: `case 'tool'` 에서 `AskUserQuestion` 이고 요약이 나오면 `AskDone` 카드 — 머리 «내가 답한 것 · 질문 N개» · 질문마다 머리말(header) + 고른 답 알약 + 직접 쓴 글. 누르면 질문 글과 고르지 않은 선택지가 펼쳐진다. 오류로 닫힌 질문(취소 · 채팅으로 답함 등 — 호스트·CLI 가 쓰는 글이 여럿이다)은 요약을 만들지 않고 종전 도구 줄 그대로 둔다(그 줄에 호스트 글이 보인다).
- 대화 기록에 이미 있는 `input`·`result` 만 읽는다 — 저장 형식은 그대로.
- **줄 짓기(`core/chatRows.buildRows`)** — 도구 줄은 늘 한 묶음으로 접힌다. 답이 읽히는 `AskUserQuestion` 줄만 묶음을 끊고 제 줄로 꺼낸다(기계는 접히지만 이것은 사람이 한 결정이다). 못 읽는 답·취소·답 전은 종전대로 묶음 안. 요약이 서면 호스트가 뒤따라 넣는 **되읊는 사람 줄**(`askEcho` — 답만 « · » 로 이은 글)은 같은 내용이라 감춘다. 답을 다 못 읽었거나(partial) 고친 글 전문이 붙은 줄은 그대로 둔다.

**검사:** `test/unit/askDone.test.ts`(세 글 모양 · `askResultText` 와 왕복 · 여럿+직접 쓴 글 · 잘린 결과 · 질문에 따옴표) · 스모크(질문 카드에 답 → `.askdone` 에 고른 답이 보임 · 펼치면 고르지 않은 선택지).

## Review Focus

- 거르개가 «허용한 태그만 다시 짓는다» 를 지키는가 — 원문 조각이 그대로 새는 길이 있는가.

## 검토 반영 (2026-11-12 · 독립 검토자)

- **막는 문제 둘** — ① 도구 줄은 늘 묶음으로 접혀 `case 'tool'` 에 요약을 넣어도 안 보인다 → `buildRows` 에서 꺼낸다(Task 4) ② `cardify` 가 `matches` 를 모른다 → `data-multi`(Task 3).
