# 여러 맥 오가기 — 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 맥 앱 하나가 여러 맥(호스트)을 기억하고, 고르면 바로 붙고, 보고 있지 않은 맥의 답 대기를 배지·알림으로 받는다. 오가는 방식은 «같은 창에서 바꾸기»(기본)와 «맥마다 창 하나»(설정).

**Architecture:** 맥 앱(`desktop/`)에 맥 목록·맥별 토큰·맥별 연결을 순수 모듈 셋으로 세우고, `main.js` 의 «호스트 하나» 가정(`settings.hostUrl`·`token`·`sse`·`states`)을 «지금 맥(active)» 과 «맥 목록» 으로 바꾼다. 화면(호스트가 내려주는 웹)은 preload 로 맥 목록을 받아 왼쪽 아래 전환기를 그리고, 앱은 붙은 맥의 판과 상관없이 네이티브 «맥» 메뉴를 늘 둔다. 호스트는 폰 홈 화면 이름을 매니페스트·`index.html` 에 채워 준다.

**Tech Stack:** Electron(CommonJS `desktop/*.js`) · React/TS 웹 화면(`src/client`) · Node 호스트(`src/host`) · vitest 유닛 · `test/smoke.mjs` · `test/mac-qa.mjs`(실 Electron + Playwright)

**Spec:** 볼트 `2. Area/제품_FolderBot/01_기획/2026-11-19_기획_여러-맥-오가기.md` (승인 11/19) · 목업 `03_디자인/2026-11-19_여러-맥-오가기-목업/여러-맥-오가기.html`

**리포:** `/Volumes/Dave HDD/dev/folderbot` (맥북) · 작업은 worktree `/Volumes/Dave HDD/dev/wt-multi-mac` · 브랜치 `feat/multi-mac`. 시작할 때 이 계획서를 리포 `docs/plans/2026-11-19_여러-맥-오가기-계획.md` 로 복사해 첫 커밋에 넣는다.

## Global Constraints

- 맥이 하나뿐인 사용자의 화면·동작은 바뀌지 않는다 — 전환기는 지금 «● mac-mini» 와 같은 모양, 창 제목·알림 제목도 그대로. 이름 붙이기는 **맥이 2대 이상일 때만**.
- 창 제목: `Folder Bot — <맥 이름>` · 알림 제목: `<맥 이름> · <원래 제목>` · 바꾸는 중 문구: `<맥 이름>로 옮기는 중…`
- 닿지 않는 맥 줄: `닿지 않음 · 마지막 HH:MM` · 5분(300,000ms) 넘게 끊기면 한 번만 알림 `<맥 이름>에 닿지 않아요` · 다시 닿으면 조용히 회복.
- Tailscale 꺼짐 안내: `Tailscale 이 꺼져 있어 다른 맥에 닿지 않아요` (판정은 `src/host/tailnet.ts` 가 아니라 맥 앱이 `tailscale status --json` 을 같은 방식으로 부른다 — `desktop/` 은 호스트 번들 없이도 돌아야 한다)
- 옛 판 맥: 창 제목 끝에 ` (옛 판 — 맥 메뉴로 바꾸세요)` · 판정은 `/api/health` 의 `macSwitcher === true` 유무.
- 단축키: ⌃⌘1 … ⌃⌘9 = 목록 순서(«이 맥» 이 맨 앞).
- 폰 이름: 매니페스트 `name` = `Folder Bot · <맥 이름>` · `short_name` 과 `apple-mobile-web-app-title` = 호스트 설정 «폰 홈 화면 이름», 비어 있으면 `FB ` + 맥 이름을 합쳐 **글자 수 12자**까지 자른 것(한글·영문 모두 한 글자를 1로 센다 — 볼트 todo 제목 규칙과 다르다).
- 폰 머리 줄의 맥 이름은 호스트에 «폰 홈 화면 이름» 을 따로 정했을 때만 보인다 — 폰은 사용자가 맥을 몇 대 쓰는지 알 수 없어서, 맥 1대 사용자의 폰 화면을 그대로 두는 신호로 쓴다(계획 단계에서 봇이 정함 · 설계 5-6 보다 좁힘).
- 맥 이름의 정본은 호스트 `hostName()`(설정 › 일반 «메인(호스트) 이름»). 맥 앱 쪽 별명은 없다. 이름은 인증된 `/api/state` 의 `hostName` 으로만 받는다 — `/api/health` 에 이름을 싣지 않는다.
- 토큰: 맥 앱 사본은 `userData/mac-tokens.json` 에 Electron `safeStorage` 로 암호화. `FOLDERBOT_QA=1` 이면 평문 코덱(검사 맥의 열쇠고리 창을 띄우지 않기 위해). 웹 화면 `localStorage['folderbot:token']` 은 그대로 둔다.
- `openMode`·`vaultLocal` 은 맥마다. 옛 값은 첫 맥으로 옮기고 새 맥은 `openMode: 'download'`.
- 원격 사본 폴더는 `remote-cache/<맥 id>/…` (맥 이름 아님).
- 화면 일은 데스크톱과 폰을 함께 검증한다(폴더 `CLAUDE.md` 2026-11-04). 검사는 `npm run qa` 와 `npm run qa:mac` 둘 다 통과해야 한다.
- 무거운 빌드·검사는 맥북에서 한다(전역 규칙 — 미니는 포화).

## Review Focus

1. **같은 맥을 다른 주소로 두 번 추가** (`100.71.x.x:7373` 과 `mac-mini.tail….ts.net`) — 붙은 뒤 `hostName` 과 `/api/health.version` 이 같은 줄이 이미 있으면 «이미 목록에 있는 맥이에요(<이름>)» 를 띄우고 새 줄을 안 만든다. → Task 1 `findDuplicate` 테스트, Task 5 연결 화면에서 사용.
2. **상대 맥에서 이 기기를 지웠다**(토큰 폐기 → 401) — 5초마다 다시 붙지 않고 그 줄을 `다시 페어링 필요` 로 표시, 고르면 연결 화면의 그 맥 페어링 칸이 열린다. → Task 3 `401 이면 auth 상태로 멈춘다` 테스트.
3. **지금 맥이 닿지 않는데 앱을 켰다/바꿨다** — 빈 창이 아니라 연결 화면이 그 맥 줄에 `닿지 않음` 을 보이고 다른 맥을 고를 수 있다. → Task 4 `loadMac` 실패 경로, Task 8 mac-qa ⑭.
4. **두 맥의 이름이 같다**(둘 다 «Mac mini») — 원격 사본·토큰·창 위치가 섞이지 않는다(전부 id 로 키). 목록에는 이름 뒤에 주소 앞부분을 덧붙여 구분. → Task 1 `displayName` 테스트, Task 4 캐시 경로 테스트.
5. **업데이트 직후 첫 실행(옮겨 담기)** — 호스트 모드 맥(Dave 의 맥미니)과 원격 모드 맥 모두 다시 페어링 없이 그대로 열리고, 맥 1대일 때 창 제목·알림·왼쪽 아래가 바뀌지 않는다. → Task 1 `migrate` 테스트, Task 8 mac-qa ⑬.

### Task 3: 맥마다 연결 하나

**Files:**

- Test: `test/unit/macLinks.test.ts` (테스트 안에서 `node:http` 로 가짜 호스트 둘을 띄운다: `/api/events` 는 SSE, `/api/state` 는 JSON)

**Interfaces:**
- Consumes: Task 1 의 `Mac`
- Produces: `createLinks(opt: { onChange(id: string): void; onNotify(id: string, n: { title: string; body: string; botId?: string; sessionId?: string }): void; onReach(id: string, ok: boolean): void; onAuthLost(id: string): void; onState(id: string, st: { hostName?: string; version?: string }): void; retryMs?: number }): { sync(macs: Mac[], tokenOf: (id) => string): void; waiting(id): number; working(id): number; busy(id): number; reachable(id): boolean; stopAll(): void }`
  - 프레임 해석은 지금 `main.js` 의 `onFrame`·`recount`·`syncState` 를 그대로 옮긴다(`state`·`sessions`·`notify`·`hello` → `/api/state` 다시 읽기). 맥마다 상태 맵이 따로다.
  - `/api/state` 응답의 `hostName`·`version` 은 `onState` 로 올린다.
  - 401 이면 `onAuthLost(id)` 를 한 번 부르고 **다시 붙지 않는다**(다음 `sync` 에서 토큰이 바뀌면 다시 붙는다).
  - 끊기면 `retryMs`(기본 5000) 뒤 다시. 닿음/끊김이 바뀔 때만 `onReach`.
  - `sync` 는 목록에서 빠진 맥의 연결을 닫고, 새 맥을 연다. 토큰이 빈 맥은 열지 않는다.

- [ ] **Step 1: 테스트**
  - 가짜 호스트 A·B 를 열고 `sync([A,B])` → A 에 `{ev:'state',sessionId:'s1',state:'awaiting_input'}` 를 보내면 `waiting('A')===1`, `waiting('B')===0`, `onChange` 가 `'A'` 로 불림
  - B 에 `{ev:'notify',n:{title:'승인',body:'x'}}` → `onNotify('B', …)`
  - A 의 토큰으로 B 에 붙이려 하면(B 가 다른 토큰만 받음) → `onAuthLost('B')` 한 번, 300ms 기다려도 B 로의 요청이 더 오지 않음(`401 이면 auth 상태로 멈춘다`)
